# DOCS SYSTEM — The Project Brain

The in-repo documentation layer, versioned in git. It records **the work itself** — mission,
current state, decisions, tasks — so any session (or any model powering Cleo) can resume from
the files alone.

## Core files

| File | Role | Rules |
|---|---|---|
| `MISSION.md` | The charter: objective, terms, constraints. | Read first. Rarely changes. |
| `MAP.md` | The always-loaded "where things live + current status" tree. | **Hard budget ~120 lines.** Regenerated by consolidation, never blindly appended. Newest/most important near the top. |
| `DECISIONS.md` | Decision log (ADR-lite): what was decided and **why**. | Newest on top. Append-only; one dated entry per decision (D1, D2, …). |
| `ops/PARTNER-TASKS.md` | Human-only task queue Cleo assigns to the partner. | Cleo adds; partner clears. |
| `docs/` | Deeper reference docs (operating model, specs, plans). | Loaded on demand via MAP. |
| `CLAUDE.md` | Session bootstrap: tells any Claude session it is Cleo and where to read. | Short — pointers, not content. |

## The retrieval rules

1. **Small working set.** Only MAP + MISSION + the current task's docs load by default.
2. Everything else is **retrieved via MAP on demand** — MAP is the router.
3. Rank by **relevance × recency × consequence** (pinned notes always present); recency alone
   is a tiebreaker.
4. **Archive = move + keep indexed.** Never delete the lossless record (git history is the
   ultimate archive; note deletions in MAP's archive index).
5. A **consolidation pass** periodically rebuilds indexes, dedupes, and archives — MAP gets
   regenerated to stay under budget, DECISIONS stays append-only as the lossless "why" trail.

## Operations (memory v2 — see MEMORY-SYSTEM.md)

| Operation | Does | Runs |
|---|---|---|
| `memctl ingest` | capture transcripts → `private/raw/`, rebuild `catalog.jsonl` | SessionStart/SessionEnd hooks, `/sleep` |
| `memctl query` / `cues` | ranked retrieval; situation-cued notes | `/wake`, on any topic shift |
| `memctl lint` / `audit` | integrity, provenance %, re-derivation audit | `/sleep`, weekly |
| `memctl night` / `wakepack` | consolidation + handoff pack | hooks + rituals |

`MAP.md` § Status holds **project** state only; direction lives in `private/GOAL-STATE.md`.
Every doc carries YAML frontmatter (`type`, `description`, `updated`) so the catalog can index it.

## Division of labor vs. memory

- **Docs** = the work: state, decisions, specs, tasks. Anyone (or any model) reading the repo
  should be able to continue the project.
- **Memory** = the relationship and cross-project continuity: who the partner is, how they want
  Cleo to operate, facts not derivable from the repo.
- One fact lives in exactly **one** place; the other side points to it if needed.

## Update discipline

- End of every session: update MAP status + append any DECISIONS + log partner tasks.
- MAP over-budget or messy → consolidate now, not "later."
- Docs describe **current state + pointers**, not narrative history (DECISIONS holds history).
